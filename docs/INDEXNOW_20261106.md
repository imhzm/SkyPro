Use a new output filename for each distinct operation. Review an existing or interrupted receipt before considering another submission. The output is created exclusively, so rerunning the same command preserves the prior receipt and stops before networking. A transport failure after starting the POST is recorded as `UNKNOWN_REVIEW_BEFORE_RETRY`. Choose another filename only after resolving that outcome.

`--plan` validates the manifest and local verification file. `--check` performs public GET checks. `--submit` performs those checks and sends one POST to the fixed IndexNow endpoint. The checks require the expected public build, matching text key, sitemap membership, HTTP200 HTML, a self-canonical and indexable robots directives for every URL. Redirects, private/foreign paths, queries, fragments and duplicate URLs fail validation.

The key in `public/indexnow.txt` is a separate public host-verification value. The CLI reads this file and records its SHA-256 fingerprint. The default application configuration supplies the public static-file route. The tool supports published created/updated pages. Deleted or redirected URLs require a separately reviewed extension to its current validation contract.

## Provider outcomes

IndexNow verifies the host through the text file. The root-level `keyLocation` covers this host. A200 response acknowledges receipt. A202 response leaves key validation pending. Rejected or ambiguous outcomes require review before retrying. Search engines determine subsequent crawling and indexing. Use one participating endpoint for the notification. Sources reviewed3November2026 are the [protocol documentation](https://www.indexnow.org/documentation) and [official FAQ](https://www.indexnow.org/faq).
